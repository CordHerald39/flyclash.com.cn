OpenClash 想让局域网中某台设备绕过代理，先确认访问控制使用的是黑名单还是白名单模式，并核对名单填的是该设备实际使用的 IP 或 MAC。这里的黑名单是绕过主机名单，白名单是代理主机名单；填对地址但选反模式，结果也会与预期不同。

## 先确定要管理的设备与范围

在本人有权限管理的路由器和局域网中操作，先记录当前 OpenClash 版本、运行模式、DNS 重定向方式和访问控制设置，并完成配置备份。只选择一台测试设备调整，不要一开始就修改覆盖整个网段的条目，避免同时影响其他用户。

确认测试设备的默认网关确实指向这台路由器。设备如果另开 VPN、手动代理或通过另一条网关访问网络，路由器侧名单不一定能够控制那条连接。测试前记录这些状态，保证前后比较的是同一条接入路径。

## 黑白名单方向要先看清

本次核验的官方 `settings.lua` 中，`lan_ac_mode` 的值 `0` 对应黑名单模式，值 `1` 对应白名单模式。黑名单下的 `lan_ac_black_ips` 与 `lan_ac_black_macs` 分别标为局域网绕过主机和绕过 MAC 名单；白名单下的 `lan_ac_white_ips` 与 `lan_ac_white_macs` 则对应局域网代理名单。

这些是源码字段，用来理解当前界面的选项关系，不要求直接修改底层文件。若只想让指定设备绕过，先对照黑名单方向核对；若想限定哪些设备进入代理，先对照白名单方向核对。不要把这里的“黑名单”理解成禁止设备联网，绕过代理与封禁访问是不同动作。

## IP 与 MAC 怎么核对

官方源码对 IP 列表使用 `ipmask` 类型，对 MAC 列表使用 MAC 地址类型。IP 条目应来自当前 DHCP 租约或已确认的静态地址；如果设备重连后获分配新地址，旧 IP 条目可能已经不再代表它。需要稳定匹配时，应先在自己的 DHCP 管理中确认地址分配关系。

MAC 也要与路由器实际看到的地址一致。手机启用私有或随机 MAC 后，不能照抄设备包装上的硬件地址；同时注意有线网卡与无线网卡属于不同接口。测试时固定使用一种网络接入，避免一边切换 Wi-Fi、一边判断名单是否生效。

## Fake-IP 下有额外显示条件

源码明确提示，在 Fake-IP 模式中使用这项功能，要把 DNS 重定向方式切换为防火墙转发。访问控制模式及 IP 名单的显示依赖中包含 `enable_redirect_dns = 2`，也包含几个 redir-host 运行模式。因此，在当前界面找不到选项时，先核对运行模式和 DNS 重定向，不要直接认定功能被删。

这条条件不能扩展成“所有模式都必须改成同一种 DNS 设置”。也不要把 LAN 名单与 WAN 绕过地址、绕过端口混为一谈；同一源码对 WAN 项还有 Fake-IP 下纯 IP 请求等限制。本文只处理局域网设备名单，目的地址绕过需要单独检查。

## 单台设备验证和恢复

保存应用后，从测试设备建立新连接，访问原来用于对照的目标，并结合 OpenClash 连接或日志记录观察是否仍进入核心。再选一台未调整的设备对照，记录预期代理或绕过的范围。路由器本机测试不能代替终端转发测试，网页能打开也不足以证明用了哪条路径。

若结果相反，先检查模式方向、实际地址和接入网关；若修改后影响正常联网，恢复备份中的名单与 DNS 设置并重新应用，再复测原路径。不要为了让名单生效清空防火墙，或同时改写整份订阅配置。
