发行页出现源码压缩包，不代表它就是 Linux 安装包。下载前应先查看资产名称和发行说明。

## 先看附件类型

在 [FlyClash Releases](https://github.com/GtxFury/FlyClash/releases) 核对每个附件的扩展名和说明。Source code 通常用于构建，不等同于面向用户的安装器；没有明确 Linux 资产时，不要把其他平台包改名使用。

## 确认架构与发布通道

即使存在 Linux 可执行文件，也要核对 x64、ARM64 等架构和正式/预发布标签。把架构、标签和下载地址记录下来，方便后续复现。

## 构建前保留边界

如果项目文档要求自行构建，先阅读依赖、命令和许可证说明。不要在生产设备上直接执行来源不明的安装脚本，也不要把个人配置放进公开构建日志。

## 连接问题单独排查

程序启动成功后再检查订阅和系统代理。启动失败、权限不足与配置解析错误分别记录，不要用换版本掩盖证据。

## 来源与边界

可用资产以开发者发行页当前内容为准。本文没有把源码包宣称为已验证的 Linux 安装器。
