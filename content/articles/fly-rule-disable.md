某条分流规则看起来让目标走错出口，可以临时停用它做对照，但不能把界面开关当成永久修改订阅的证明。FlyClash v0.2.9 规则列表会读取内核提供的额外状态，并根据规则索引发送切换请求。

## 先找到规则，不先点开关

在匹配规则列表中，记录当前配置、运行模式和目标请求。可以按规则类型、载荷或出口名字查找。[MatchRules 组件](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/src/components/MatchRules.tsx)按这些字段筛选，但搜索只是改变显示范围，不会自动改变实际规则顺序。

重名的规则或相似域名可能有多个结果。先保存规则类型、载荷和显示位置，再与同一次请求的命中记录核对。不要因为名称里包含目标域名就认定它一定是优先命中的规则。

## 看见开关需要什么条件

固定版本组件根据 rule.extra 是否存在显示切换入口，用 extra.disabled 展示停用状态。没有对应开关时，不能假装所有内核版本都支持它，也不应自行构造控制 API 请求。

它使用读取列表时生成的索引定位规则。因此配置重载或列表刷新后，应重新找目标规则，不拿之前记住的序号继续操作。规则索引不是永久身份。

## 一次只停用一条已核对规则

1. 保存当前配置及目标规则的原状态。
2. 对一条确实相关的规则执行临时停用，等待请求结束。
3. 刷新规则列表，确认该对象的状态，再对同一目标建立新请求。
4. 记录命中与出口是否发生预期变化。
5. 恢复该规则原状态，再重复一次请求确认回退。

源码在切换时会先更新界面；发生错误时重新读取列表。因此刚点击后出现的划线或变色，不能替代刷新后的内核状态。测试前应避开重要会话，不批量停用整套规则。

## 对照结果怎样解释

| 结果 | 合理的下一步 |
| --- | --- |
| 停用后命中变化 | 保留两次记录，定位该规则的作用 |
| 停用后毫无变化 | 核对其他更早匹配的规则及当前运行模式 |
| 切换报错并恢复列表 | 保留错误，确认内核功能与客户端版本 |
| 重载后状态不同 | 核对运行时与配置文件状态，不能推导永久保存 |

持久化修改应另外核对你使用的配置管理方式。本文只说明这一版本的临时观察与回退，不承诺停用状态在重启、更新订阅或换内核后继续保留。

## 版本与反馈材料

2026-10-04 核对上述固定 v0.2.9 组件以及[mihomo 官方规则语义](https://wiki.metacubex.one/config/rules/)。规则是运行配置的一部分，普通匹配规则的先后关系值得与具体模式一起读；不要把搜索后的可见顺序当成新运行顺序。

本页未调用控制接口或修改你的规则。反馈保留客户端及内核版本、脱敏规则、原状态、切换错误和两次请求结果，隐藏完整配置和敏感域名。若规则集合没更新，另看[规则提供者更新](/articles/fly-rule-providers/)。
