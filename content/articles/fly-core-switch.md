内核下载完成，运行中的代理未必已经换到该版本。FlyClash 的客户端发行、内核文件下载和内核切换是不同阶段。本文依据桌面正式版 v0.2.9 的内核管理组件与 IPC，不把仓库 main 后续改动当成正式发行功能。

## 记录两种版本和一份基线

先记录 FlyClash 客户端版本、当前内核类型与版本、配置名称以及一条授权请求的结果。保留旧内核和原配置，不要在确认新版本之前删除唯一可用文件。

[CoreManager 组件](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/src/components/CoreManager.tsx)分别加载当前配置、已安装内核和可下载版本。它包含稳定、alpha 等不同类型以及稳定版指定版本的处理；选项名称并不能保证每种内核对你的配置同样兼容。

## 下载、选择和运行分阶段核对

| 阶段 | 要确认的结果 |
| --- | --- |
| 选择目标 | 核对版本、来源与平台，不把 alpha 当作默认推荐 |
| 下载 | 文件完成取得与处理，已安装列表出现预期对象 |
| 切换 | 切换请求成功，当前内核信息显示目标 |
| 连接 | 原配置能够启动，同一授权请求按预期完成 |

界面在下载成功后刷新已安装列表和当前信息；切换使用单独的 coreSwitchCore 请求。即使下载进度到达 100%，还可能处于处理阶段，不能因此跳过完成状态。

稳定版选择具体版本时，组件用单独的指定版本类型来处理；不要在未选择具体版本的情况下强行进行指定版本切换。[IPC 实现](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/electron/ipc-handlers/core-manager-ipc.js)也将下载、切换、删除和自定义路径分别注册。

## 切换前结束重要会话

内核变化可能影响连接和可用配置，应在允许中断的时间验证。先保存工作，再只改变内核版本，不同时更换订阅、DNS 和路由。切换完成后重新读取当前信息，启动配置并建立新请求，记录错误和实际行为。

客户端能显示一个内核类型，不代表你可以忽略该内核自身的发行说明。涉及字段或协议差异，应对照目标内核的官方文档；本页不提供让所有配置跨版本通用的保证。

## 失败时保留原配置回退

| 观察 | 回退重点 |
| --- | --- |
| 下载失败 | 保留原内核，记录下载错误和目标版本 |
| 下载成功但切换失败 | 核对切换结果，不反复删除重下 |
| 切换成功但配置启动失败 | 保存错误，切回原内核再验证原配置 |
| 当前版本已变，单个目标异常 | 保留同一请求对照，检查与版本相关的行为 |

不要在新版本首次成功启动后立即清理旧文件。至少完成你需要的真实场景验收，再决定是否删除不再使用的版本。本文不执行安装下载或自定义路径变更。
