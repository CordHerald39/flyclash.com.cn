Windows 上有些受 AppContainer 限制的应用，不能像普通桌面程序一样访问本地代理。FlyClash 的回环管理针对这种边界，不是给所有网络故障通用的“修复按钮”。本页以桌面正式版 v0.2.9 的源码为依据，Android 不适用。

## 先确认故障确实在本地入口

使用你自己的 Windows 设备，记录 FlyClash 版本、应用名称以及实际本地代理端口。先确认客户端运行，普通桌面应用能够通过同一入口访问授权目标。如果所有应用都失败，应先处理客户端或端口问题，暂不改回环豁免。

也不要把所有来自商店的应用都认作相同类型。项目的[回环实现](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/electron/loopback-manager.js)枚举 AppContainer，再整理显示名称与当前豁免状态；列表中是否出现目标对象，是更具体的检查线索。

## 在列表中核对身份和原状态

打开 Windows 对应的回环管理入口，搜索目标应用。重名或名称不完整时，应结合包身份核对，不凭图标相似就操作。记录原来是否已豁免，同时保留其他已有应用的状态。

[界面源码](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/src/components/LoopbackManager.tsx)将尚未保存的修改单独存放。勾选发生变化，不等于系统状态已经写入。完成保存后应刷新列表，并确认目标应用实际状态，而不是只看按钮颜色。

## 只对一个目标做对照

1. 记录目标应用的原状态，确认同一代理入口在基线中可用。
2. 只修改该应用的回环豁免选择，保留其他已有状态。
3. 保存后刷新列表，检查状态是否反映本次操作。
4. 重新打开目标应用或建立新请求，使用同一个授权目标验收。
5. 若无改善，恢复该应用原值并保存，再核对恢复结果。

不要使用“全选”作为第一次排查。回环豁免改变的是隔离应用访问本机网络的边界，应该由明确需要本地代理的目标驱动。

## 观察结果能说明什么

| 结果 | 下一步 |
| --- | --- |
| 列表无法加载 | 记录平台、错误和版本，不凭空添加包名 |
| 保存后刷新状态不变 | 保留保存错误，先解决写入环节 |
| 状态已变，目标仍不能连接 | 检查目标的代理方式、端口与实际错误 |
| 目标恢复，其他应用不受影响 | 记录这一个应用的对照结果，避免扩大结论 |

源码实现使用 Windows 网络隔离相关 API。实际操作可能受设备管理策略等条件影响，不宜仅凭源码注释推导每台设备都无需任何授权处理。

## 回退与正式版范围

排查后恢复不需要的临时豁免，保留你确认需要的应用清单。本页没有执行 Windows 网络设置变更，也未进行商店应用实测，不保证所有商店应用都接受本地代理。
