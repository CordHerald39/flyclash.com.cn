媒体检测显示“完全支持”，也不等于你自己的账号能够播放任意节目；显示“超时”，也不能立刻解释为节点被封。FlyClash 使用具体探测请求生成结果，本页帮助你理解正式桌面版 v0.2.9 的观察范围。

## 先固定本次测试对象

记录客户端版本、实际代理端口、当前使用的配置与选择组。确认已有一个授权的新请求能够正常通过客户端，再运行你设备上的检测。不要在检测中途切换节点或修改运行模式。

后台的[检测实现](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/electron/mediatest.js)从用户设置取得代理端口，前端[结果组件](https://github.com/GtxFury/FlyClash/blob/937d348ff8c0507ee5b7030b4a4d16b3d9201a2d/app/components/MediaStreamingTest.tsx)调用检测接口并整理 available、fullSupport 与错误。页面显示的“当前节点”只是记录的一部分，实际路径仍应与运行配置、规则和入口一起核对。

## 分开读状态与文字原因

| 状态 | 能据此判断的范围 |
| --- | --- |
| 完全支持 | 当前实现对本次探测给出了完整支持结果 |
| 部分支持 | 探测可用，但未满足完整支持判定 |
| 不支持或错误 | 本次检查返回不可用或失败，需要读原因 |
| 超时 | 检查没有及时完成，不能单独确定地区限制 |
| 检测中或空闲 | 尚未得到可用于比较的最终结果 |

代码将探测结果转换为这些状态，服务页面解析、网络可达性与响应内容都会影响判定。本文不转录测试请求里的固定参数，也不要求你提供媒体账号或付费 API 凭据。

## 复测应保留相同条件

先保存首次结果、时间和错误摘要，再对同一服务复测。若只是一个服务超时，保留该服务的完整错误类型；不要同时换 DNS、出口和内核，让前后样本失去可比性。

出现“部分支持”时，阅读该次说明，再用你有权使用的账号与内容做实际播放验收。涉及会员、内容授权或地区条款的条件，应以服务方规则与真实播放结果为准。检测结果不会替你购买会员，也不能承诺后续一直可用。

## 报告截图不应扩大含义

分享结果时注明日期、客户端版本、检测服务及出口代号。不要将一次绿色结果包装成全部地区、全部内容或永久解锁证明。若还没有实际播放，明确写“仅完成客户端探测，未做播放验证”。

探测失败但普通请求可用时，把两个结果一起记录；这样比只发一个红色图标更容易解释故障范围。日志中可能包含 IP、请求地址和设置，分享前应隐藏个人信息。
