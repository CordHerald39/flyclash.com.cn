sing-box 在电脑上能用，局域网手机却连不上，应先检查代理入站监听在哪里。监听在 `127.0.0.1` 的服务仅接受本机回环连接；其他设备需要访问电脑可达的局域网地址，并且该入站确实在对应地址和端口上监听。

## 把监听问题与节点问题分开

记录电脑局域网 IP、入站类型、监听端口与手机所在网络。先在电脑本机验证同一入站；若本机也连不上，优先检查内核是否启动、配置是否加载，以及日志有没有端口占用或绑定地址不存在的错误。

官方 Listen Fields 把 `listen` 定义为必填监听地址，`listen_port` 为监听端口。`mixed` 入站同时提供 SOCKS 与 HTTP 服务，但使用哪种协议仍要和手机应用中的代理设置对应。它不能让任意不支持代理的应用自动经过这个端口。

## 按需要确定监听范围

只供本机使用时保留回环地址。确需给自己的局域网设备使用时，可以绑定电脑当前的局域网地址，并核对该地址在重启或换网后是否变化。绑定 IPv4 通配地址 `0.0.0.0` 会扩大到所有本机 IPv4 接口，应先确认访问范围与防火墙规则。

在手机上填写电脑局域网 IP，不能填写 `127.0.0.1`；手机上的回环地址指向手机自己。也不要把电脑对外的公网地址当作局域网监听地址。无需为了局域网使用建立路由器公网端口映射。

## 建立一组能复现的测试

1. 备份配置，在原入站中修改监听地址，保留类型、端口和已有用户设置，不要重复新增同端口入站。
2. 执行 `sing-box check`，重载后查看实际监听地址与进程。配置可解析不代表端口绑定成功。
3. 用同一局域网设备测试该 IP 和端口；若连不通，核对访客 Wi-Fi 隔离、设备所在网段和系统防火墙，仅为需要的网络范围添加规则。
4. 端口可达后再验证 HTTP 或 SOCKS 协议与认证；最后才检查节点和 DNS。各阶段保留独立结果。

官方 Mixed 文档指出，`users` 为空时不要求认证。扩大监听范围前应核实访问控制；已有认证排错可看 [Mixed 用户认证检查](/articles/sing-box-mixed-users-authentication/)。不要为了解决连接失败同时关闭防火墙和认证，这会使测试条件变化过多。

## 回退与继续定位

测试结束后，若不再共享，恢复回环监听并撤销本次添加的访问规则。若本机可用、远端端口仍不可达，保留两端地址和连接结果，继续检查局域网路径；若端口可达但代理请求失败，参考 [Mixed 入站配置](/articles/sing-box-mixed-inbound-config/) 核对协议。无需重装全部客户端。
