FlClash 原始 README 列出通过本地文件或 WebDAV 备份和恢复的能力。迁移时应先确认备份能够被目标版本读取，再验证配置与连接。备份文件生成成功，不等于已经证明恢复成功，也不表示所有平台权限都能自动迁移。

## 先建立可回滚的备份

1. 记录当前 FlClash 版本、操作系统、配置来源和代理模式。
2. 使用当前版本提供的备份功能保存本地文件，核对文件大小、时间和保存位置。
3. 保留一份不在即将清理或重装目录中的副本，避免卸载时一并删除。
4. 如使用 WebDAV，另行记录服务地址与认证信息的安全保存位置，不将密码写进公开迁移笔记。

具体菜单名称和备份范围可能随版本变化，应以当前界面和发行说明为准。README 只确认功能存在，不能据此断言某个版本一定备份所有日志、缓存、系统权限或外部文件。

## 本地文件与 WebDAV 分别检查什么

| 方式 | 需要核实的结果 |
| --- | --- |
| 本地文件 | 文件实际存在、位置可访问、能被恢复入口识别 |
| WebDAV | 登录可用、远端路径正确、上传成功且可读取 |
| 双份保留 | 一份副本失效时，仍有另一份完整备份 |

WebDAV 连接成功不代表文件已经上传完成。先在远端确认备份对象，再保留一个本地副本；不要把尚未验证的同步操作当成唯一备份。

## 先验证副本，再清理旧环境

在允许回滚的环境中恢复备份，核对配置列表、当前选中配置、规则和代理组选择是否符合预期。不要在导入失败时连续覆盖同一份唯一备份。订阅更新依赖原服务仍有效，恢复旧配置也不会自动延长订阅期限。

备份可能包含订阅链接、节点凭据、WebDAV 信息或其他私人配置，应按敏感文件处理。不上传到公开 Issue，也不放进公开 Git 仓库。需要求助时只分享脱敏后的错误和字段结构。

## 跨平台迁移后的检查

Android 的 VPN 授权与按应用代理，以及桌面的系统代理、TUN 或托盘设置，都需要在目标设备重新核对。不要假设备份能把操作系统权限一并带过去。

恢复后选定一个节点和一个目标，检查解析、连接与实际出站；成功后再逐项恢复自定义规则。Windows 安装见[FlClash Windows 下载](/articles/flclash-windows-download/)，Android 见[安装与授权说明](/articles/flclash-android-install/)。确认目标环境可用并且副本完整后，再安排清理旧设备。
