v2rayN 自定义路由 JSON 导入后没有按预期分流，先检查它是不是规则数组、目标规则是否启用，以及前面有没有更宽的规则先命中。系统代理负责把部分应用流量送进核心，路由负责核心收到流量之后的出口选择，两步都需要核对。

## 先从客户端导出一份参照

官方 Wiki 说明，自定义规则内容是一个数组，每一项是一条规则，也可以在路由规则中多选后导出到剪贴板参考。先备份当前可用的路由方案，并用当前版本的导出结果确认格式，避免把完整 Xray 配置或一个裸对象粘进只接受规则数组的入口。

不要直接覆盖所有既有条目。先在独立的测试方案或备份副本中增加一条能判断结果的规则，保存后检查条目数量、启用状态及当前选中的方案。界面入口名称可能随版本调整，以当前软件提供的规则导入、编辑和导出功能为准。

## 一个局域网直连示例

下面采用官方示例中的局域网 IP 直连规则，只演示规则数组形状，不包含最终代理兜底。它不是可直接替换整份核心配置的文件：

```json
[
  {
    "port": "",
    "outboundTag": "direct",
    "ip": ["geoip:private"],
    "enabled": true,
    "remarks": "局域网 IP 直连"
  }
]
```

`ip` 是数组，`enabled` 是布尔值，不能写成字符串 `"true"`。`remarks` 是便于自己识别的备注；出口由 `outboundTag` 指定。官方客户端示例使用 `direct`、`proxy`、`block`，不要仅修改备注就期待出口变化，也不要编造一个不存在的标签。

`geoip:private` 依赖核心能读取对应规则数据。出现数据文件加载错误时，先修复相关资源；JSON 语法正确，不代表运行依赖齐全。本文只按使用 Xray 的情形说明规则判断，不把其他核心的字段和资源行为视为完全相同。

## 兜底规则为什么要靠后

Xray 官方路由文档说明，每个连接按规则从上到下判断，第一个生效的规则决定出口。v2rayN 官方示例也把 `port` 为 `0-65535`、出口为 `proxy` 的最终代理规则放在后面。如果把这样的宽泛条目放在局域网规则之前，后面的例外便可能没有机会命中。

检查顺序时先找范围最大的条件，再看特定域名、IP 或端口例外所在的位置。为了排查一条局域网规则，不必同时导入广告拦截、全部 UDP 阻断和复杂域名集，否则出现变化时很难定位是哪一条造成的。

## 流量进核心后再看命中

保存方案后，确认客户端实际采用了它，再检查系统代理或应用代理是否指向当前核心入口。官方系统代理说明强调它只转发操作系统部分软件的流量，所以某个应用没有记录时，应先查接入路径，不能仅靠调整规则顺序解决。

从有权限访问的局域网服务发起一次请求，结合当前日志检查是否出现预期直连出口；再用正常需要代理的目标对照原方案的行为。每次测试建立新连接，避免沿用已有连接误判。若方案无法加载或影响原有访问，恢复备份并重新启动服务，保留出错提示，先处理格式或资源错误再继续增加规则。
