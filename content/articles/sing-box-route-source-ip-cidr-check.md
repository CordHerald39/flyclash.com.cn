sing-box 要让局域网某个网段使用指定出口，应先检查核心看到的来源地址，再配置 source_ip_cidr。官方将这个字段定义为来源 IP CIDR 匹配，而 ip_cidr 匹配目标 IP。把终端所在网段写进目标地址条件，无法表达“来自这些设备”的需求。

## 确认入站保留了什么来源

记录客户端、核心版本、接管方式与实际入站标签，保留原配置。让一台准备纳入分流的设备发起新请求，查看核心连接记录中的来源地址。如果流量经另一代理转发，或者已经经过会改写来源地址的 NAT，核心记录的可能是中间设备地址，不能直接沿用终端系统里显示的地址。

本机应用经本地代理接入时，也可能在记录里表现为回环地址。此时一条终端局域网网段规则未命中，并不能证明 CIDR 写法有错。先确认流量确实经过计划中的入站，再考虑是否应该改用入站、进程等其他可观察条件。

## 把来源条件放在 route.rules

下面展示一条规则，须加入已有 route.rules，而非替换完整配置。192.168.50.0/24 是示例私网网段，proxy-existing 是示例出口标签；必须按实际来源和已有出口修改。

```json
{
  "source_ip_cidr": ["192.168.50.0/24"],
  "action": "route",
  "outbound": "proxy-existing"
}
```

不要为了让规则覆盖更多设备，随意把网段扩大到整个地址空间。先用需要处理的一个实际网段进行验证，确认 CIDR 的网络范围、当前 DHCP 分配和核心记录一致。若设备使用 IPv6，另核对它实际使用的 IPv6 来源；IPv4 网段无法据此覆盖所有 IPv6 连接。

配置动作引用的出口应先能独立连接。保存后检查配置语法、标签存在性和重载结果。检查失败时恢复备份，避免把未启动的新配置与仍在运行的旧配置混作一次测试。

## 避免把多个条件读错

官方默认规则采用字段组组合逻辑：来源地址条件与目标域名、端口等条件组之间存在同时满足的要求。例如一条规则既限定 source_ip_cidr 又限定某个目标端口，它表达的是来源和端口的组合条件，而非来自这个网段的所有流量都命中。

初次排查可以先保留一个来源条件，检查前面是否已有规则处理目标请求，再逐项增加需要的限制。有关目标连接协议可接着看[TCP 与 UDP 分流](/articles/sing-box-route-network-tcp-udp/)。

## 用两台设备或两个来源做对照

从目标网段发起一条新连接，再从范围外的来源发起相同目标请求。记录来源地址、入站、时间和出口。若两次在核心里都显示同一个上游地址，先处理来源信息边界；若来源不同却同走一个出口，检查规则顺序、组合条件与默认出口是否掩盖了差别。

验收标准是实际观察到的来源符合条件，并通过预期出口建立连接。此配置只处理已进入核心的流量，不能代替路由器访问控制，也不会自动让局域网设备改用这台代理。修改后出现异常时，撤回新规则并恢复原配置即可。
