FlClash 一键导入链接点击后没反应，先区分系统有没有唤起 FlClash，以及 FlClash 有没有拿到完整订阅地址。官方格式是 `clash://install-config?url=` 后接经过 URL 编码的订阅链接，`clashmeta://` 和 `flclash://` 开头的同类链接也受支持。

## 先确认打开的是正确软件

FlClash 与名称接近的 FlyClash 是不同项目。先从本站 FlClash 独立软件入口核对官方仓库，并确认本机已安装相应客户端。浏览器出现“打开外部应用”的提示时，核对目标名称；如果打开了另一款客户端，应检查系统协议关联，而不是反复修改订阅内容。

本文只说明已有授权订阅的导入方式，不提供公共订阅地址，也不把其他软件的分享链接当成整份配置。一个网页 URL、单节点链接和能够返回 Clash 配置的订阅 URL，实际内容可能不同，需要按提供方说明分清。

## url 参数要保留整个地址

官方说明里的尖括号内容是格式说明，不能原样当作可用链接。实际处理时，将你自己的完整订阅地址作为一个值做 URL 编码，再放入外层链接的 `url` 参数。不要只编码域名，也不要先截掉订阅地址中的查询参数。

订阅地址如果本来就包含 `?`、`&` 或 `#`，直接拼接到外层链接可能改变参数边界。典型现象是客户端打开了，却只拿到地址的前半段。正确做法是对完整内部 URL 编码一次，然后在本地核对解码后能还原为原地址；如果反复编码，解码一次仍可能残留被转义的文本。

## 根据源码检查固定部分

本次核验的官方 `lib/common/link.dart` 中，配置提取函数要求 URI 的主机部分为 `install-config`，并读取查询参数 `url`。该值去掉首尾空白后为空，就不会作为配置地址继续处理。因此，拼写成其他路径、使用全角符号，或漏写 `url` 的链接，都应先修正结构。

源码的二维码处理还会判断提取结果是不是 URL。由此可见，“能被扫码识别”与“已经完成远程下载”属于不同阶段。不要因为扫描器返回了一串文字，就断定订阅格式、远端权限和 YAML 内容都通过检查。

## 按三段定位失败点

第一段是浏览器或系统唤起。点击后完全没有客户端动作，先保存当前配置，检查安装与协议关联，再尝试从客户端现有导入入口直接输入原始订阅地址。不同系统的关联恢复方式不同，不建议为了这个问题删除全部应用数据。

第二段是地址传递。客户端打开但没有正确地址时，检查 `install-config` 与 `url`，比较内部 URL 编码前后是否一致。订阅地址可能含个人标识，应在本地比较，不要把完整链接发到公开论坛，也不要把它当搜索关键词提交。

第三段是下载与激活。能够进入导入流程但提示下载或解析失败，转到订阅响应检查；成功新增配置后，还要确认当前选择的是新条目，核心加载无报错，并从目标应用发起请求。若新配置异常，切回原来可用条目，再保留错误信息排查。一次唤起成功只能证明入口工作，不能替代连接验收。
